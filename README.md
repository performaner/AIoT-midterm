# 閃電對決 v7.1 · UNO Q Reaction Duel

兩人共用一把 PC 鍵盤，看 UNO Q 的 LED 燈號搶按。支援經典、綠燈按紅燈停、紅燈按綠燈停三種玩法。每局結束顯示比分，打完設定局數後播放勝負跑馬燈。

本專案開發過程使用 AI 協助進行程式設計、除錯、測試案例撰寫、文件整理與介面內容規劃。硬體連線、遊戲規則與實際試玩仍由開發者確認。

## 開始遊玩

1. 安裝 Python 3.11+（含 tkinter）。只用標準函式庫，不需安裝額外套件。
2. 在 Arduino App Lab 停止舊 App，匯入 **`dist/uno_q_reaction.zip`** 並執行 **Reaction Duel v7.1**。
3. 雙擊 `start_game.cmd`，或執行 `python reaction_game.py`。
4. 選「UNO Q 燈號」，按 **「一鍵連線 UNO Q」**，不需要填 IP 或 port。
5. 確認 LED 顯示 `0:0`，選擇玩法。要打正式比賽時，在「比賽局數」填入 **1 到 99**（預設 5），按「開始」或在欄位按 Enter。

每次有一方得分才算完成一局。逾時、雙方成功忍住或取消的局會重打。打完設定局數後，得分較高者獲勝，同分則平手。例如設定 4 局，比分 3:0 仍會打第 4 局，最終比分 2:2 就判平手。要改局數，先按「重新比賽」。

沒有板子時可選「PC 綠燈（離線練習）」，同樣可以打正式比賽或 30 秒練習。30 秒練習會自動連續出題、不計分，不使用局數設定。

畫面統計顯示每位玩家的有效反應平均與最快時間、偷跑及禁止色誤按次數。勝率以本次開啟程式期間已結束的正式比賽計算；重開程式會歸零。練習的反應與失誤另行統計，不影響正式比分或勝率。

## 三種遊戲模式

| 模式 | 綠色 | 紅色 |
|---|---|---|
| 經典搶快 | 搶按 | 不會出現 |
| 綠燈按・紅燈停 | 搶按 | 不可按 |
| 紅燈按・綠燈停 | 不可按 | 搶按 |

顏色模式每回合隨機選擇紅或綠。按到禁止顏色，對手得一分；禁止顏色維持 2 秒，雙方都不按則比分不變，按空白鍵繼續。該按的顏色出現後 5 秒無人按，重賽。

**看的是 UNO Q 的 MCU RGB 指示燈 LED3。13×8 點陣只有藍色，不會變紅／綠。**
等待時 RGB 亮藍色，開始時 RGB 變紅／綠。藍色點陣從等待到出題都維持熄滅，回合結束後才顯示結果。

## 玩法

| 操作 / 燈號 | 意義 |
|---|---|
| 玩家 1：預設 A；玩家 2：預設 L | 搶按，請用英文輸入法。開賽前點玩家卡上的「更改」，按英文字母或數字設定，Esc 取消 |
| 空白鍵 | 開始下一回合；比賽結束先重置，再按一次開始 |
| RGB 藍燈 | 等待，提前按會判偷跑，對手得分 |
| RGB 紅／綠 | 根據本場規則判斷是否要按 |
| LED `2:1` 等數字 | 左玩家 1、右玩家 2，保留至下一回合 |
| F11 / Esc | 全螢幕 / 離開全螢幕 |

全場結束先顯示最終比分 1.5 秒，再循環跑馬顯示 `Congratulations! Player 1 WIN`、`Congratulations! Player 2 WIN` 或 `TIE`（平手）。LED 可顯示雙位數比分，例如 `12:10`。
練習時，回合結束的點陣會顯示圈圈（成功反應／成功忍住）或叉號（失誤／逾時）；30 秒結束顯示 `P`，RGB LED 同步以綠、紅、藍提示。練習期間不顯示 0:0，避免被誤認為正式比分。正式比賽有效按鍵後也先顯示圈圈約 0.7 秒，再自動切到比分或冠軍畫面。
點陣以 5×7 大寫字型呈現，PC 顯示完整混合大小寫文字。重新比賽會立即停止跑馬燈並顯示 `0:0`。

確認板上等待燈號後，隨機等待 2～5 秒才切換開始燈號。五秒無人按鍵不計分重賽。
按住按鍵不會重複得分；視窗失去焦點會取消進行中的回合。重新比賽按鈕直接清空比分。
板子模式中 PC 不會顯示「搶！」，必須看 UNO Q。

## 連線與版本更新

PC 與 UNO Q 必須能在 USB 網路或區域網路互通，且先在 App Lab 執行 v7。
「一鍵連線」優先驗證上次成功的位址、USB 常用位址 `192.168.7.2`，再尋找本機網卡所在區域網路。
只探測遊戲的固定 HTTP 連接埠，確認應用程式名稱、版本與 MCU 回應才連線，不會把一般網站誤認為板子。
首次搜尋可能需要數秒至約半分鐘；找到多台時會列出讓你選擇，後續會記住成功連線。
同一板子的多個介面會依接收器識別名稱合併。紀錄放在 `.local/connection.json`，不提交到 Git。
接收器會保留閒置連線 60 秒，讓 PC 在正常的 2～5 秒等待後沿用同一條連線出燈。若玩家休息較久，PC 會在送出下一個燈號前自動重連。

若沒找到：先確認 App Lab 正在 Run；再按「手動 IP（備用）」，只填 `192.168.1.121` 這類 IP，然後按一鍵連線。系統自動補上 8765。
IP 可在 UNO Q 終端用 `hostname -I` 查詢。跨網段、訪客 Wi-Fi 隔離、大型子網路或 VPN 可能影響搜尋。
搜尋每個介面只探測其所在的最多 /24 範圍，合計不超過 1024 個位址；手動 IP 可用來指定此範圍外的板子。

新版日誌會顯示 `Reaction Duel v7 LED receiver listening on port 8765`。
本版使用 `show_duel_v7`、`duel_version` 與 `/health` 探索端點。**PC、接收器與 sketch 必須一起更新**。PC 會拒絕舊版回覆。
`app.yaml` 已包含 `ports: [8765]`。若有 listening 日誌仍被拒絕連線，確認使用最新 ZIP，停止後重新 Run。

PowerShell 測試：`Test-NetConnection 192.168.1.121 -Port 8765`（換成實際 IP）。
HTTP 400 通常是舊 PC 協定或資料錯誤；503 代表 Bridge / sketch 失敗，請查 App Lab 日誌。
接收器沒有認證，只應用在可信任區域網路，不要公開 8765 至網際網路。

## 音效

音效由 **Windows PC 的喇叭／耳機**播放，不需要 UNO Q 蜂鳴器。沒有外部套件或下載素材，全部以程式合成 WAV。
正式比賽只在得分和全場結算時播放音效。每局由玩家按空白鍵開始，等待與燈號切換時保持安靜。取消左上角的「音效」即可靜音。
音效非阻塞播放，不會等待音樂結束才接受按鍵。系統靜音或音效不可用不影響計分；音效功能使用 Windows 的 winsound。

## 公平性與限制

- 等待及開始燈號都需板子成功回覆；斷線或回覆逾時取消該回合。
- 按鍵若發生在開始命令傳送與確認之間，無法確定相對於實際亮燈的先後，因此不計分重賽。
- UNO Q 模式以 PC 收到鍵盤事件的順序決定勝者。兩邊首次有效按鍵都可顯示反應時間；誤按禁止顏色時顯示犯規者的時間。
- 板子燈號送出時間為 `t0`、成功回覆時間為 `t1`；估計亮燈時間取 `(t0+t1)/2`，反應時間為按鍵時間減此估計值。
- 例如「約 250 ms（±20 ms 網路區間）」代表網路往返 40 ms。這是命令執行時間的估計，不是量測實際 LED 光線變化；還有顯示刷新、鍵盤與系統排程延遲。不能當成精密測量或宣稱固定精度。
- PC 練習模式仍顯示毫秒數，但顯示器與鍵盤延遲使它不適合科學測量。
- v3 經使用者試玩回報沒有太大問題。v4 已做軟體與原生 C++ 模擬測試；新版呼吸動畫、自動搜尋與音效體驗仍待實際板子及環境確認。

## 專案結構與開發

- `reaction_game.py`：遊戲與桌面介面。
- `board_link.py`：背景網路連線。
- `discovery.py`：一鍵探索、接收器驗證與記住位址。
- `sound_effects.py`：合成音效與非阻塞播放。
- `uno_q_reaction/`：App Lab 原始碼與設定。
- `dist/uno_q_reaction.zip`：可匯入專案。
- `tests/`：遊戲、接收器與模擬介面狀態測試。
- `tools/package_app.py`：重新打包工具。
- [CHANGELOG.md](CHANGELOG.md)：需求變更與修改過程。

```powershell
python -m unittest discover -s tests -v
python tools/package_app.py
```

有安裝 `g++` 時會額外編譯並執行 sketch 的原生模擬測試；沒有時略過該項。此測試不等同 Arduino 工具鏈編譯。

舊動畫與拆彈程式已從目前版本移除，可從 Git 歷史查閱。
